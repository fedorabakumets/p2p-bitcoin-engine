# P2P Bitcoin Engine

Прототип обменника BTC за рубли. Клиент работает через обычного Telegram-бота на aiogram 3. Mini App не нужен.

Этот репозиторий — этапы 0–2: пользователь, котировка, заявка и клиентское меню. Денег на платформе нет, трейдер не назначается.

## Как запустить

Нужны Docker и токен бота. Токена в репозитории нет: его нужно получить у BotFather и положить в окружение, когда он будет.

```bash
cp .env.example .env
# позже: впишите BOT_TOKEN в .env
docker compose up --build
```

Compose поднимает PostgreSQL, Redis и приложение. Контейнер приложения сначала применяет миграции, затем запускает бота. Пока `BOT_TOKEN` пустой, процесс завершается с понятным текстом и без трассировки aiogram. Postgres и Redis при этом остаются запущенными.

Проверка здоровья: `GET /healthz` на порту 8000.

Локально, без Docker:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -e ".[dev]"
export DATABASE_URL=postgresql+asyncpg://p2p:p2p@127.0.0.1:5432/p2p
export REDIS_URL=redis://127.0.0.1:6379/0
export BTC_RUB_RATE=6000000
alembic upgrade head
python -m app.main --dry-run
pytest
```

`python -m app.main --dry-run` не ходит в Telegram и не требует `BOT_TOKEN`. Он печатает котировку на 2000 ₽ по курсу из `BTC_RUB_RATE`.

Когда токен появится:

```bash
export BOT_TOKEN=...
python -m app.main
```

## Что делает прототип

- `/start` создаёт пользователя. Ссылка `ref_<code>` записывает `referred_by_user_id`. Самого себя пригласить нельзя. Повторный `/start` реферера не меняет.
- Меню: Купить BTC, Мои заявки, Партнёрская программа, Поддержка.
- Покупка: сумма в рублях (это сумма, на которую клиент получает BTC), затем BTC-адрес (`bc1`, `1` или `3`), затем котировка. «Продолжить» сохраняет снимок и заявку и переводит её в `SEARCHING_EXECUTOR`. Клиенту сообщают, что ищется трейдер.
- «Мои заявки» показывает заявки этого клиента. Партнёрский экран показывает `t.me/<username>?start=ref_<code>` и число приглашённых. Если username бота неизвестен, показывается только код.
- Курс читается из `BTC_RUB_RATE` (по умолчанию 6 000 000 ₽ за BTC). Наценка, комиссия платформы, доля реферала и TTL котировки читаются из таблицы `settings`.

Кнопки вызывают сервисный слой напрямую. FastAPI в этом прототипе — только `GET /healthz`. Redis нужен для таймера диалога и лимита сообщений, не для захвата заявки.

## Чего прототип не делает

- не назначает трейдера и не захватывает заявку;
- не двигает escrow и ledger;
- не подключает Electrum и не отправляет биткоин;
- не принимает рубли и не ходит в платёжный процессор;
- не открывает Mini App, умный роутинг и админ-сайт.

## Как устроены деньги

В ledger только биток, в сатоши. Рубли на платформу не приходят: клиент переводит всю сумму на карту трейдера. Наценка в рублях остаётся на карте трейдера и в ledger не проводится.

Клиент получает биток на сумму «получите». С депозита трейдера списывается больше. Разница — комиссия платформы, из неё же берётся партнёрское начисление. Партнёрский баланс тоже в битках.

Снимок котировки копируется в заявку. Поздний курс старую заявку не пересчитывает.

- `client_btc_sats` — сколько уйдёт клиенту, биток за principal по зафиксированному курсу
- `platform_fee_sats` — сколько останется платформе
- `referral_sats` — часть комиссии платформы, не добавка сверху
- `trader_lock_sats` = `client_btc_sats` + `platform_fee_sats`

Рубли хранятся целыми копейками. Стартовые настройки в миграции: жизнь котировки 120 секунд, окно «принять» 20 секунд, время на оплату 900 секунд, наценка 1800 б.п. (18%), комиссия платформы и доля реферала 0.

Клиент вводит principal в рублях. К оплате = principal × (1 + наценка). При 2000 ₽ и 18% к оплате 2360 ₽.

## Схема

Описание таблиц: [docs/schema-v1.md](docs/schema-v1.md).

Первая миграция Alembic применяет [migrations/001_initial.sql](migrations/001_initial.sql) как есть. Ledger не переводится в рублёвые балансы.

Статусы заявки: `CREATED`, `QUOTED`, `SEARCHING_EXECUTOR`, `EXECUTOR_ASSIGNED`, `WAITING_PAYMENT`, `CLIENT_MARKED_PAID`, `PAYMENT_CONFIRMED`, `RELEASING`, `COMPLETED`, а также `CANCELLED`, `EXPIRED`, `DISPUTED`, `FAILED`. Переходы проверяет сервис заявок и пишет `order_events`. После `CLIENT_MARKED_PAID` клиент заявку не отменяет.
